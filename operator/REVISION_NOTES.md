# Revision 3: reproduce the reviewed-ID operation

Adds exactly one explicit material-only route for a previously independently reviewed, source-bound ID mapping. It retains all revision-2 material-reference, ancestor-feature, serializer-domain, source-binding, no-overwrite and preservation guards. It accepts only the observed finite common pure-translation compose storage form, copies it untouched, and never uses it or stored translation ranks as proof of physical mapping. The identity-only lattice route remains separate and unchanged.

Both actual private audited mappings pass the reviewed-ID route and reproduce the delivered candidate archives byte for byte in isolated temporary outputs. Full private audits are retained separately; temporary project copies are removed. All actual inputs and delivered files remain unchanged. No private plan, filename/path, raw material evidence, ID, workbook, project or render is included in this source package.

The operator must perform actual label/geometry review and supply independent expected values. A hash binds that reviewed mapping to the exact inputs; it does not prove the review happened. Native material/compose semantics and open/recompose/save acceptance remain unverified. See `REVIEWED_ID_MODE.md`.

The initial and revision-2 packages are preserved unchanged. The revision-2 history below explains guard changes; its identity-only refusal still applies to that route, not to the new explicit reviewed-ID material-only route.

## Prior revision 2


The first review package is retained unchanged. No actual input, delivered conversion or native-validation file was modified by these repairs. No supported source version or geometry class was broadened.

1. Material UUID accounting includes **all occurrence nodes**, including ancestor containers, and **all tray-body material definitions**, including preserved unrelated bodies. A changed target UUID must have exactly its own desired occurrence and actual tray-body references. Ancestor inheritance or a body-only alias can no longer create conflicting definitions after a change. Existing shared native black is allowed only when preserved.
2. Exactly passive feature state is required throughout the occurrence hierarchy. Active `uniqueFeatures`, nonempty `currentStateIndices`, unknown keys or missing feature state are refused on ancestors as well as leaves.
3. Compose semantics were not established by the existing evidence. The revised placement profile therefore requires an explicit exactly identity `composeTransform` on every body. Common translations are refused too; apparent uniformity or an algebraic translation interpretation is not native evidence. Unknown placement values are never repaired in the input. The profile identifier changes to `conservative-2170-cm-quarterturn-identity-compose-v2` so old plans are not silently treated as meeting the revised contract.
4. `check-plan` executes the unchanged material serializer on each requested sample recipe during preflight. Values that sum exactly to 100 but cannot survive the serializer's binary64 decimal domain fail before a plan is reported valid. Safe serializer rejection is retained.

The 48 tests include direct reproductions of ancestor/shared UUIDs, preserved unrelated body-only aliases, active/missing ancestor features, common and differential compose translations, compose rotation/missing state, and high-precision preflight refusal. Existing preservation, native black metadata, source binding and no-overwrite tests remain.

Private read-only impact checking found neither ancestor material assignments nor active ancestor feature state in the two historical inputs. Both contain translated compose transforms, so this revision refuses those cases. That is a conservative future-use limitation, not a finding that independently audited past cell assignments are incorrect. Native material semantics and ordinary open/recompose/save acceptance remain unresolved; this package does not retroactively certify or invalidate them.

Publication remains coordinated by the parent workflow. The source package contains no private data or vendor runtime/database, and adds no new license grant.
